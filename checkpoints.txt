# Aven implementation checkpoints

This file is the delivery tracker for the project. Each checkpoint has a matching document in `docs/` that explains the service, its classes, data flow, and design choices.

## Checkpoint 1 — Ledger Service (in progress)

Goal: establish the immutable, balanced double-entry ledger before introducing asynchronous infrastructure.

- [x] Create the ledger schema through Flyway migrations.
- [x] Model immutable transactions and entries.
- [x] Implement balanced transaction validation and atomic persistence.
- [x] Implement idempotency using the `Idempotency-Key` header.
- [x] Implement reversal transactions without changing original records.
- [x] Implement paginated account-entry history.
- [ ] Add PostgreSQL/Testcontainers integration coverage for the HTTP API.
- [x] Document the Ledger Service design and request flows.

Exit criteria: a client can create a balanced transaction once, repeat the same request safely, inspect immutable entries, and create a compensating reversal.

## Checkpoint 2 — Ledger outbox and Kafka publishing

- [ ] Create the shared versioned event contract module.
- [ ] Write the transaction event and outbox record atomically.
- [ ] Publish unpublished outbox records safely and mark them published only after Kafka acknowledgement.
- [ ] Demonstrate recovery after Kafka is unavailable.
- [ ] Document the outbox flow and failure semantics.

## Checkpoint 3 — Account Service projection

- [ ] Add account lifecycle APIs and migrations.
- [ ] Consume ledger events into a derived balance cache.
- [ ] Make event handling idempotent with `processed_events`.
- [ ] Add balance API and consumer recovery tests.
- [ ] Document the projection and duplicate-delivery behavior.

## Checkpoint 4 — Settlement Service

- [ ] Add the Settlement Service module and schema.
- [ ] Batch pending transactions.
- [ ] Simulate settlement outcomes deterministically in tests.
- [ ] Implement exponential retry and dead-letter handling.
- [ ] Document settlement states and retry flow.

## Checkpoint 5 — Reconciliation Service

- [ ] Independently replay ledger events into computed balances.
- [ ] Compare computed balances with Account Service balances.
- [ ] Persist and emit specific drift findings.
- [ ] Add a controlled local-only drift demo.
- [ ] Document reconciliation assumptions and Kafka-retention limits.

## Checkpoint 6 — Gateway, Compose, and scripted demo

- [ ] Add gateway routes and correlation-ID propagation.
- [ ] Add Dockerfiles, Kafka, and one PostgreSQL instance per service to Compose.
- [ ] Add Makefile targets and HTTP/demo scripts.
- [ ] Complete the architecture README and a failure/recovery walkthrough.

## Checkpoint 7 — Stretch hardening

- [ ] Add distributed tracing.
- [ ] Run a documented chaos scenario (Kafka or consumer interruption).
- [ ] Add reversal and observability polish required for interviews.
